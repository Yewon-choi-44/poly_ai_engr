## 1. Controller 코드 및 URL 매핑

### `BookController.java` — 도서 CRUD + 이미지 업로드 (전문)

```java
package com.aitech.library.book;

import java.io.File;
import java.sql.Connection;
import java.sql.SQLException;
import java.text.SimpleDateFormat;
import java.util.Date;
import java.util.List;

import javax.sql.DataSource;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.ResponseBody;
import org.springframework.web.multipart.MultipartFile;

import com.aitech.library.book.BookDao;

@Controller
public class BookController {

	private static final String uploadDir = System.getProperty("user.dir") + "/upload/book_images/"; //파일 저장 경로

	@Autowired
	private BookDao bookDao;

	public BookController(BookDao bookDao) {
		this.bookDao = bookDao;
	}

	@RequestMapping("/booklist")
	public String booklist(Model model) {
		List<BookVo> books = bookDao.getAllBook();
		model.addAttribute("books",books);
		return "book/book_list";
	}

	@RequestMapping("/registerbook")
	public String registerbook() {
			return "admin/register_book";
		}


	@RequestMapping("/registerbookconfirm")
	public String registerbookconfirm(BookVo bookVo,
			@RequestParam("b_img_file") MultipartFile file) throws Exception {
		if(!file.isEmpty()) { // 선택 파일이 있으면
			bookVo.setB_img(saveBookImg(file)); // 실제 파일명.확장자만 DB 저장
		}
		bookDao.insertBook(bookVo);
		return "redirect:managementbook";
	}


	private String saveBookImg(MultipartFile file) throws Exception {
		File dir = new File(uploadDir);

		if(!dir.exists())
			dir.mkdirs();

		String fileName = new SimpleDateFormat("yyyyMMdd_HHmmss_").format(new Date())
				+ file.getOriginalFilename();
		file.transferTo(new File(uploadDir + fileName));
		return fileName;
	}

	private void deleteBookImg(String b_img) {
		if(b_img != null && b_img.isEmpty()) {
			new File(uploadDir + b_img).delete();
		}
	}


	@RequestMapping("/managementbook")
	public String managementbook(Model model) {
		List<BookVo> books = bookDao.getAllBook();
		model.addAttribute("books",books);
		return "admin/management_book";

	}

	@RequestMapping("/bookdetail")
	public String bookDetail(@RequestParam("b_no") int b_no, Model model) {
		model.addAttribute("book", bookDao.getDetailBook(b_no));
		return "book/book_detail";

	}


	@RequestMapping("/modifybook")
	public String modifybook(@RequestParam("b_no") int b_no, Model model) {
		model.addAttribute("book", bookDao.getDetailBook(b_no));
		return "admin/modify_book";
		}


	@RequestMapping("/modifybookconfirm")
	public String modifybookconfirm(BookVo bookVo, @RequestParam("b_img_file") MultipartFile file) throws Exception {

		BookVo oldBook = bookDao.getDetailBook(bookVo.getB_no());

		if(!file.isEmpty()) {
			bookVo.setB_img(saveBookImg(file));
			deleteBookImg(oldBook.getB_img());
		} else {
			bookVo.setB_img(oldBook.getB_img());
		}
		bookDao.updateBook(bookVo);
		return "redirect:managementbook";
	}


	@RequestMapping("/deletebook")
	public String deletebook(@RequestParam("b_no") int b_no) {
		BookVo oldBook = bookDao.getDetailBook(b_no);
		bookDao.deleteBook(b_no);
		deleteBookImg(oldBook.getB_img());
		return "redirect:managementbook";
	}
}
```

#### 동작 원리

- **필드 주입 이중화**: `@Autowired private BookDao bookDao;`(필드 주입)와 생성자 `public BookController(BookDao bookDao)`(생성자 주입)가 동시에 존재합니다. Spring이 빈을 생성할 때 먼저 생성자를 호출해 파라미터로 받은 `bookDao`를 필드에 대입하고, 그 직후 `@Autowired`가 붙은 필드에 컨테이너가 다시 한 번 같은 빈을 주입합니다. 결과적으로 같은 값이 두 번 세팅될 뿐 오류는 나지 않지만, 생성자 주입만으로 충분하므로 필드의 `@Autowired`는 불필요한 중복입니다.
- **`booklist()` 흐름**: 브라우저가 `GET /booklist`를 요청 → Spring이 `@RequestMapping("/booklist")`가 붙은 메서드를 찾아 호출 → `bookDao.getAllBook()`이 DB에서 전체 행을 조회해 `List<BookVo>`로 반환 → `model.addAttribute("books", books)`로 이 리스트를 Model에 담음 → 컨트롤러가 문자열 `"book/book_list"`를 반환하면, `application.properties`의 `spring.mvc.view.prefix`/`suffix` 설정에 따라 View Resolver가 이를 `/WEB-INF/views/book/book_list.jsp`로 변환해 포워드(forward)함 → JSP가 Model에 담긴 `books`를 EL(`${books}`)로 꺼내 화면을 렌더링.
- **`registerbookconfirm()` — 커맨드 객체 바인딩**: 메서드 파라미터 `BookVo bookVo`는 커맨드 객체(command object)입니다. Spring MVC가 폼에서 전송된 `name` 속성값(`b_name`, `b_author` 등)과 `BookVo`의 setter 이름을 매칭해 자동으로 값을 채워 넣습니다(`name="b_name"` → `setB_name()` 호출). 별도의 `@RequestParam` 없이도 폼 필드가 통째로 객체에 매핑되는 것이 이 구조의 핵심입니다.
- **파일 업로드 흐름(`saveBookImg`)**: `<input type="file" name="b_img_file">`로 전송된 파일은 `@RequestParam("b_img_file") MultipartFile file`로 받습니다. `file.isEmpty()`로 실제 파일 선택 여부를 먼저 확인한 뒤(선택 안 하면 빈 `MultipartFile`이 옴), `saveBookImg()`에서 업로드 폴더가 없으면 `mkdirs()`로 생성하고, `SimpleDateFormat("yyyyMMdd_HHmmss_")`로 만든 타임스탬프를 원본 파일명 앞에 붙여 충돌 없는 새 파일명을 만든 다음 `file.transferTo()`로 디스크에 실제 저장합니다. DB에는 파일 전체 경로가 아니라 이 파일명만 저장되고(`bookVo.setB_img(...)`), 실제 서빙은 `application.properties`의 `static-locations` 설정이 담당합니다.
- **PRG 패턴**: 등록/수정/삭제 처리 메서드는 모두 `return "redirect:managementbook"`으로 끝납니다. View를 직접 반환하는 대신 브라우저에 302 리다이렉트 응답을 보내 `/managementbook`을 다시 GET 요청하게 만드는 방식으로, 사용자가 새로고침(F5)해도 폼이 중복 제출되지 않습니다.
- **수정 시 이미지 유지 로직**: `modifybookconfirm()`은 수정 폼 제출 시 `bookDao.getDetailBook(bookVo.getB_no())`로 DB에 저장된 기존 데이터(`oldBook`)를 먼저 조회합니다. 새 파일이 첨부됐으면 새로 저장하고 기존 파일을 지우며(`deleteBookImg`), 파일을 첨부하지 않았으면 `bookVo.setB_img(oldBook.getB_img())`로 기존 파일명을 그대로 유지합니다. 이렇게 하지 않으면 이미지 없이 폼을 제출할 때 `b_img`가 `null`로 덮어써져 기존 이미지 링크가 끊깁니다.
- **삭제 흐름**: `deletebook()`은 DB 행을 지우기(`bookDao.deleteBook`) 전에 먼저 `getDetailBook(b_no)`로 이미지 파일명을 확보해 둔 뒤, DB 삭제 후 `deleteBookImg()`로 실제 파일도 지우려 시도합니다(다만 `deleteBookImg`의 조건식 버그로 실제로는 삭제되지 않음 — "발견된 이슈" 참고).

## 2. Model 및 View 연결 구조

```
GET /bookdetail?b_no=3
   └─▶ BookController.bookDetail()
         ├─ bookDao.getDetailBook(3) ─▶ DB SELECT * FROM book WHERE b_no = ?
         │       └─ BookVo 단건 반환 (JdbcTemplate.queryForObject)
         └─ model.addAttribute("book", book)
               └─▶ JSP: book/book_detail.jsp
                         ${book.b_name}, ${book.b_author} ... 단건 상세 출력

POST /registerbookconfirm (multipart/form-data)
   └─▶ BookController.registerbookconfirm(BookVo, MultipartFile)
         ├─ 파일 있으면 saveBookImg() → /upload/book_images/에 저장, 파일명 DB 컬럼(b_img)에 세팅
         ├─ bookDao.insertBook(bookVo) ─▶ DB INSERT
         └─ redirect:managementbook (PRG 패턴 — 새로고침 시 중복 등록 방지)
```

**동작 원리**: `Model`은 Spring MVC가 Controller와 View 사이의 데이터 전달을 추상화한 인터페이스입니다. `model.addAttribute(key, value)`로 담은 값은 내부적으로 `request.setAttribute(key, value)`와 동등하게 동작해, JSP 쪽에서 `${key}` EL 표현식으로 꺼낼 수 있습니다. `DispatcherServlet`이 Controller가 반환한 논리적 뷰 이름(`"book/book_detail"`)을 받아 `InternalResourceViewResolver`(prefix/suffix 설정)로 실제 파일 경로(`/WEB-INF/views/book/book_detail.jsp`)를 조합하고, 그 JSP로 요청을 **forward**합니다(이 경우 클라이언트 URL은 바뀌지 않음 — 주소창에는 여전히 `/bookdetail?b_no=3`이 보입니다).

**정적 리소스 매핑 확장** (`application.properties`)

업로드된 이미지를 웹에서 직접 서빙할 수 있도록 `static-locations`에 업로드 디렉토리를 추가:

```properties
spring.web.resources.static-locations=classpath:/static/,file:${user.dir}/upload/book_images/
```

→ JSP에서 `<img src="${book.b_img}">`처럼 파일명만으로 바로 접근 가능 (예: `/20260922_170106_9788954682152.jpg`). Spring Boot의 `ResourceHttpRequestHandler`가 요청 경로를 `static-locations`에 나열된 위치들에서 순서대로 찾아보기 때문에, DB 컬럼에는 파일명만 저장해도 실제 파일시스템 경로(`user.dir/upload/book_images/`)와 자동으로 연결됩니다.

## 3. DB 연동 코드 — `JdbcTemplate` 방식으로 전환 완료

이전 버전(`until_260922_mon`)은 `BookDao`가 `DataSource`를 직접 사용하는 순수 JDBC 방식이었으나, 오늘 `JdbcTemplate` + `BookRowMapper` 조합으로 리팩터링되었습니다.

### `BookDao.java` (전문)

```java
package com.aitech.library.book;

import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;

import javax.sql.DataSource;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Repository;

@Repository
public class BookDao {
//	private DataSource dataSource;
	private JdbcTemplate jdbcTemplate;

//	public BookDao(DataSource dataSource) {
//		this.dataSource = dataSource;
//	}
	@Autowired
	public BookDao(JdbcTemplate jdbcTemplate) {
		this.jdbcTemplate = jdbcTemplate;
	}


	public void insertBook(BookVo bookVo) {
		String sql = "INSERT INTO book(b_name, b_author, b_publisher, b_publish_year, "
				+ "b_isbn, b_call_number, b_rental_able, "
				+ "b_img, b_reg_date, b_mod_date) " + "VALUES(?, ?, ?, ?, ?, ?, ?, ?, now(), now())";

		jdbcTemplate.update(sql, bookVo.getB_name(), bookVo.getB_author(),
				bookVo.getB_publisher(), bookVo.getB_publish_year(), bookVo.getB_isbn(),
				bookVo.getB_call_number(), bookVo.getB_rental_able(), bookVo.getB_img() );
	}



	public List<BookVo> getAllBook() {
		String sql = "SELECT * FROM book ORDER BY b_no";
		return jdbcTemplate.query(sql, new BookRowMapper());
	}

	public BookVo getDetailBook(int b_no) {
		String sql = "SELECT * FROM book WHERE b_no = ?";
		return jdbcTemplate.queryForObject(sql, new BookRowMapper(), b_no);
	}


   	public void updateBook(BookVo bookVo) {
   			String sql = "UPDATE book SET b_name = ? , b_author = ? , b_publisher = ? , "
   					+ "b_publish_year = ? , b_isbn = ? , b_call_number = ? , b_rental_able = ? , "
   					+ "b_img = ? , b_reg_date = now() , b_mod_date = now() WHERE b_no = ?";
   			jdbcTemplate.update(sql, bookVo.getB_name(), bookVo.getB_author(), bookVo.getB_publisher(),
   					bookVo.getB_publish_year(), bookVo.getB_isbn(), bookVo.getB_call_number(), bookVo.getB_rental_able(),
   					bookVo.getB_img(), bookVo.getB_no());
   	}

   	public void deleteBook(int b_no) {
   		String sql = "DELETE FROM book WHERE b_no = ?";
   		int rows = jdbcTemplate.update(sql, b_no);
   	}

}
```

#### 동작 원리

- **생성자 주입 + 미사용 필드**: `DataSource dataSource` 필드와 그 생성자는 통째로 주석 처리되어 있고, 실제로 활성화된 생성자는 `JdbcTemplate`을 직접 주입받습니다. Spring 컨테이너가 `DBconfig`에서 등록한 `jdbcTemplate` 빈을 찾아 이 생성자에 넘겨주며, 이때부터 `BookDao`는 `Connection`/`PreparedStatement`를 직접 열고 닫는 책임에서 완전히 벗어납니다.
- **`insertBook`**: SQL 문자열에 `?` 플레이스홀더 8개를 두고, `jdbcTemplate.update(sql, 값1, 값2, ...)`처럼 가변인자로 값을 순서대로 넘기면 `JdbcTemplate`이 내부적으로 `PreparedStatement`를 생성해 각 `?`에 `setString`/`setInt` 등을 알맞게 호출해 줍니다. `b_reg_date, b_mod_date`는 애플리케이션 값이 아니라 SQL의 `now()` 함수로 DB 서버 시각을 그대로 사용합니다.
- **`getAllBook` / `getDetailBook`**: `jdbcTemplate.query(sql, rowMapper)`는 SQL을 실행해 나온 모든 행에 대해 `BookRowMapper.mapRow()`를 호출하고 그 결과를 `List`로 모아 반환합니다. `queryForObject`는 정확히 한 행만 기대하는 버전으로, 결과가 0건이거나 2건 이상이면 예외(`EmptyResultDataAccessException`/`IncorrectResultSizeDataAccessException`)를 던집니다 — 즉 `b_no`가 존재하지 않는 값으로 `/bookdetail`을 호출하면 500 에러가 발생할 수 있는 구조입니다.
- **`updateBook`**: `WHERE b_no = ?`로 특정 행만 골라 전체 컬럼을 `?`로 다시 세팅하는 "전체 컬럼 UPDATE" 방식입니다. `SET` 절 마지막의 `b_reg_date = now()`가 등록일까지 현재 시각으로 덮어쓰는 부분은 의미상 버그입니다(아래 "발견된 이슈" 참고) — `b_mod_date`(수정일)만 갱신 대상이어야 합니다.
- **`deleteBook`**: `jdbcTemplate.update()`의 반환값은 영향받은 행 수(int)이며, 여기서는 `rows` 변수에 담아두기만 하고 실제로 사용(로깅/검증)하지는 않습니다.

> ⚠️ `updateBook()`의 SQL이 `b_reg_date = now()`도 함께 갱신합니다. 등록일은 최초 등록 시점을 유지해야 하므로, 수정 시에는 `b_mod_date`만 `now()`로 갱신하고 `b_reg_date`는 갱신 대상에서 빼는 것이 의미상 맞습니다 — 아래 "발견된 이슈" 참고.

### `DBconfig.java` (전문, 변경 없음)

```java
package com.aitech.library.config;

import javax.sql.DataSource;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.PropertySource;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.datasource.DriverManagerDataSource;

@Configuration
@PropertySource("classpath:db.properties")
public class DBconfig {
	@Value("${db.driver}")
	private String driver;

	@Value("${db.url}")
	private String url;

	@Value("${db.username}")
	private String username;

	@Value("${db.password}")
	private String password;

	@Bean
	public DataSource dataSource() {
		DriverManagerDataSource dataSource = new DriverManagerDataSource();
		dataSource.setDriverClassName(driver);
		dataSource.setUrl(url);
		dataSource.setUsername(username);
		dataSource.setPassword(password);
		return dataSource;
	}
	@Bean
	public JdbcTemplate jdbcTemplate(DataSource dataSource) {
		return new JdbcTemplate(dataSource);
	}
}
```

#### 동작 원리

- `@PropertySource("classpath:db.properties")`는 클래스패스(`src/main/resources/db.properties`)에 있는 파일을 Spring의 `Environment`에 로드합니다. 이렇게 로드된 키-값 쌍은 `@Value("${db.driver}")`처럼 필드 주입 시 참조할 수 있습니다.
- `dataSource()` 빈 메서드는 `DriverManagerDataSource`(커넥션 풀 없이 요청마다 새 `Connection`을 여는 가장 단순한 구현체)를 만들어 driver/url/username/password를 세팅해 반환합니다. 스프링 컨테이너가 이 메서드 반환값을 빈으로 등록해두면, 이후 다른 빈들이 `DataSource` 타입으로 주입받을 수 있습니다.
- `jdbcTemplate(DataSource dataSource)`는 메서드 파라미터로 위에서 등록한 `dataSource` 빈을 자동으로 주입받아 `JdbcTemplate`을 감싸 반환합니다. `BookDao`의 생성자가 요구하는 `JdbcTemplate` 타입이 바로 이 빈입니다.

> ⚠️ `db.properties`는 민감 정보(username, password)를 포함하므로 `.gitignore`(`**/db.properties`)에 등록되어 있음을 재확인 — 현재 git 추적에서 정상 제외된 상태.

### `BookRowMapper.java` (전문) — 실제로 사용되기 시작

이전 아카이브에서는 "추후 전환 예정"으로 남겨졌던 `RowMapper`가, 오늘 `BookDao`가 `JdbcTemplate` 기반으로 바뀌면서 `getAllBook()` / `getDetailBook()` 양쪽에 실제로 사용됩니다.

```java
package com.aitech.library.book;

import java.sql.ResultSet;
import java.sql.SQLException;

import org.springframework.jdbc.core.RowMapper;

public class BookRowMapper implements RowMapper<BookVo>{

	@Override
	public BookVo mapRow(ResultSet rs, int rowNum) throws SQLException {
		BookVo book = new BookVo();
		book.setB_no(rs.getInt("b_no"));
		book.setB_name(rs.getString("b_name"));
		book.setB_author(rs.getString("b_author"));
		book.setB_publisher(rs.getString("b_publisher"));
		book.setB_publish_year(rs.getString("b_publish_year"));
		book.setB_isbn(rs.getString("b_isbn"));
		book.setB_call_number(rs.getString("b_call_number"));
		book.setB_rental_able(rs.getInt("b_rental_able"));
		book.setB_img(rs.getString("b_img"));
		return book;
	}

}
```

#### 동작 원리

- `JdbcTemplate.query()`/`queryForObject()`는 SQL을 실행해 얻은 `ResultSet`을 순회하며, 각 행마다 `mapRow(rs, rowNum)`을 한 번씩 호출합니다. `rowNum`은 현재 행의 0-based 순번(여기서는 미사용). 컬럼명(`"b_no"` 등)으로 값을 꺼내기 때문에 SQL의 `SELECT *`가 반환하는 컬럼 순서가 바뀌어도(테이블 스키마 변경 등) 안전하게 동작합니다. `mapRow`가 반환한 `BookVo`들을 `JdbcTemplate`이 모아 `List<BookVo>`로 돌려주거나(`query`), 정확히 한 개만 기대하는 경우 그 객체 하나만 돌려줍니다(`queryForObject`).
- `b_reg_date`, `b_mod_date`는 이 매퍼에서 매핑되지 않고 있습니다 — `getAllBook`/`getDetailBook` 결과의 등록일/수정일 필드는 항상 `null`로 남습니다. 현재 화면(목록/상세/관리)에서 등록일·수정일을 표시하지 않으므로 당장 문제는 없지만, 추후 이 값을 화면에 노출하려면 매퍼에 두 줄을 추가해야 합니다.

#### 동작 원리

- `spring.mvc.view.prefix`/`suffix`: Controller가 반환한 논리 뷰 이름 앞뒤에 이 값을 붙여 실제 JSP 파일 경로를 완성합니다 (`"book/book_list"` → `/WEB-INF/views/book/book_list.jsp`). `WEB-INF` 아래에 둔 이유는 이 경로가 외부에서 직접 URL로 접근할 수 없는 보호된 영역이기 때문입니다(반드시 Controller → ViewResolver를 거쳐야만 도달 가능).
- `spring.servlet.multipart.max-file-size` / `max-request-size`: Spring Boot가 내장 톰캣의 Multipart 설정(`MultipartConfigElement`)에 이 값을 적용합니다. 파일 하나의 최대 크기와, 여러 파트(파일+텍스트 필드 전체)를 합친 요청 전체의 최대 크기를 각각 제한하며, 초과 시 `MaxUploadSizeExceededException`이 발생합니다. 기본값(1MB)로는 대부분의 표지 이미지가 거부되기 때문에 10MB로 올린 것입니다.
- `spring.web.resources.static-locations`: 콤마로 구분된 여러 위치를 순서대로 정적 리소스 검색 경로로 등록합니다. `classpath:/static/`(기존 기본값, jar 내부 정적 파일)에 더해 `file:${user.dir}/upload/book_images/`(런타임에 생성되는 실제 파일시스템 경로)를 추가해, 업로드된 이미지를 별도 Controller 코드 없이 URL로 바로 서빙할 수 있게 했습니다.

#### 동작 원리

- `/modifybook?b_no=3` 요청으로 Controller가 `model.addAttribute("book", bookDao.getDetailBook(3))`를 해둔 상태에서 이 JSP가 렌더링되므로, 모든 `value="${book.xxx}"`가 EL을 통해 DB에서 조회한 기존 값으로 채워져 "수정 전 값이 미리 채워진 폼"이 됩니다.
- `${book.b_rental_able == 1 ? 'selected' : ''}`는 EL의 삼항 연산자로, 현재 값이 1이면 `<option>`에 `selected` 속성 문자열을 그대로 끼워 넣어 해당 옵션이 기본 선택되게 합니다.
- 이미지 표시부는 등록 폼에는 없던 `c:choose`/`c:when`/`c:otherwise` 분기가 추가되어, `book.b_img`가 비어있지 않으면 기존 이미지를 미리보기로 보여주고, 없으면 placeholder 박스를 보여줍니다. 이 아래 `<input type="file" name="b_img_file">`로 새 파일을 선택하면 `BookController.modifybookconfirm()`에서 교체 로직이 실행됩니다.
- **버그**: `<input type="hidden" name="b_no" value="${book.b_no}"` 줄 끝에 닫는 `>`가 없습니다. HTML 파서는 다음에 등장하는 `>`(바로 아래 줄의 `<label class="form-label">도서명</label>`의 `>`가 아니라, 파서가 속성 목록이 계속되는 것으로 해석하다가 만나는 첫 `>`)까지를 이 `<input>` 태그의 속성 선언부로 취급할 가능성이 높아, 의도한 `<label>`이 사라지거나 레이아웃이 깨질 수 있습니다.

| `BookDao.getDetailBook()` | 존재하지 않는 `b_no`로 상세/수정 페이지 접근 시 500 에러 | `queryForObject`는 결과가 0건이면 `EmptyResultDataAccessException`을 던지는데, Controller에 예외 처리가 없음 |

## 💡 핵심 문법 정리 표 (Key Takeaways)

| 개념 | 설명 | 예시 |
| :--- | :--- | :--- |
| `MultipartFile` | Spring MVC에서 업로드 파일을 표현하는 인터페이스 | `@RequestParam("b_img_file") MultipartFile file` |
| `multipart/form-data` | 파일 전송을 위한 HTML 폼 인코딩 타입 | `<form enctype="multipart/form-data">` |
| `spring.servlet.multipart.*` | 업로드 파일/요청 크기 제한 설정 | `max-file-size=10MB` |
| `MultipartFile.transferTo()` | 업로드된 파일을 서버 디스크에 저장 | `file.transferTo(new File(path))` |
| `spring.web.resources.static-locations` | 정적 리소스 서빙 경로를 다중 지정 (클래스패스 + 파일시스템) | `file:${user.dir}/upload/book_images/` |
| 커맨드 객체(Command Object) 바인딩 | 폼 `name` 속성과 VO의 setter를 자동 매칭해 통째로 객체를 채움 | `registerbookconfirm(BookVo bookVo, ...)` |
| `JdbcTemplate.queryForObject` | 단건 조회 결과를 `RowMapper`로 매핑해 반환 (0건/다건이면 예외) | `jdbcTemplate.queryForObject(sql, mapper, b_no)` |
| `JdbcTemplate.query` | 다건 조회 결과를 `List<T>`로 매핑해 반환 | `jdbcTemplate.query(sql, new BookRowMapper())` |
| PRG 패턴 (Post/Redirect/Get) | POST 처리 후 GET으로 리다이렉트해 새로고침 시 중복 제출 방지 | `return "redirect:managementbook"` |
| JSTL `c:choose`/`c:when`/`c:otherwise` | 조건부 분기 렌더링 (Java if-else에 대응) | 이미지 유무에 따른 썸네일/placeholder 분기 |
| `${not empty 표현식}` | EL에서 null/빈 문자열/빈 컬렉션 여부 판별 | `${not empty book.b_img}` |
| EL 삼항 연산자 | 조건에 따라 속성값(문자열)을 다르게 삽입 | `${book.b_rental_able == 1 ? 'selected' : ''}` |
| `<c:forEach varStatus="status">` | 반복 중 순번(`status.count`) 등 메타정보 접근 | `${status.count}` |
| 파일명 타임스탬프 접두어 | 동일 파일명 업로드 시 덮어쓰기 방지 패턴 | `SimpleDateFormat("yyyyMMdd_HHmmss_")` |
| forward vs redirect | forward는 서버 내부 전달(URL 유지), redirect는 브라우저 재요청(URL 변경) | 일반 View 반환=forward, `redirect:경로`=redirect |
