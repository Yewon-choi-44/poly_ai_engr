### 예외 처리 우선순위

```

  ├─ ③ web.xml <exception-type> 일치? ────▶ 매핑된 페이지
```

#### ① 📄 `errorPage.jsp` — errorPage 속성으로 오류 페이지 지정
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<%@ page errorPage="errorPage_error.jsp"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	name 파라미터 : <%=request.getParameter("name").toUpperCase()%>
</body>
</html>
```
**동작 원리:**
- `?name=...` 파라미터 없이 열면 `request.getParameter("name")`이 `null` → `.toUpperCase()`에서 **`NullPointerException`** 발생
- `<%@ page errorPage="errorPage_error.jsp"%>` 덕분에 Tomcat 기본 오류 화면 대신 지정한 페이지로 이동합니다.
- `errorPage.jsp?name=apple`로 열면 정상적으로 `APPLE`이 출력됩니다.

#### 📄 `errorPage_error.jsp`
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	오류가 발생하였습니다.
</body>
</html>
```
**동작 원리:**
- `isErrorPage="true"`가 없으므로 `exception` 내장 객체를 쓸 수 없고, 고정 안내 문구만 표시합니다.

---

#### ② 📄 `isErrorPage.jsp` — isErrorPage 오류 페이지로 이동
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<%@ page errorPage="isErrorPage_error.jsp"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	name 파라미터 : <%=request.getParameter("name").toUpperCase()%>
</body>
</html>
```
**동작 원리:**
- ①과 같은 오류를 일으키지만, 이동할 오류 페이지가 `isErrorPage="true"`로 선언된 페이지입니다.

#### 📄 `isErrorPage_error.jsp` — exception 내장 객체 사용
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<%@ page isErrorPage="true"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	<p>오류가 발생하였습니다.
	<p>예외 유형 : <%=exception.getClass().getName()%>
	<p>오류 메시지 : <%=exception.getMessage()%>
</body>
</html>
```
**동작 원리:**
- `<%@ page isErrorPage="true"%>`: 이 페이지가 오류 처리 전용임을 선언 → **`exception` 내장 객체**(`java.lang.Throwable`)를 사용할 수 있게 됩니다.
- `exception.getClass().getName()`: `java.lang.NullPointerException`
- `exception.getMessage()`: 예외 메시지 (NPE는 JDK 버전에 따라 `null` 또는 상세 메시지)

---

```jsp

<html>

<title>Exception</title>
</head>
<body>
	<form action="exception_process.jsp" method="post">
		<p>숫자1 : <input type="text" name="num1">
		<p>숫자2 : <input type="text" name="num2">
		<p><input type="submit" value="나누기">
	</form>
</body>
</html>
```

#### 📄 `exception_process.jsp` — 나눗셈 처리 (errorPage 지정)
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<%@ page errorPage="exception_error.jsp"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	<%
		String num1 = request.getParameter("num1");
		String num2 = request.getParameter("num2");
		int a = Integer.parseInt(num1);
		int b = Integer.parseInt(num2);
		int c = a / b;
		out.print(num1 + " / " + num2 + " = " + c);
	%>
</body>
</html>
```
**동작 원리:**
- 숫자가 아닌 값 → `Integer.parseInt()`에서 **`NumberFormatException`**
- 숫자2에 `0` → `a / b`에서 **`ArithmeticException: / by zero`**
- 어느 쪽이든 `errorPage="exception_error.jsp"`로 이동

#### 📄 `exception_error.jsp` — exception 객체 메서드 출력
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<%@ page isErrorPage="true"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	<p>오류가 발생하였습니다.
	<p>예외 : <%=exception%>
	<p>toString() : %=exception.toString()%>
	<p>getClass().getName() : <%=exception.getClass().getName()%>
	<p>getMessage() : <%=exception.getMessage()%>
</body>
</html>
```
**동작 원리:**
- `<%=exception%>`: 객체를 출력하면 내부적으로 `toString()`이 호출됨 → `java.lang.ArithmeticException: / by zero`
- `getClass().getName()`: 예외 클래스 이름만 / `getMessage()`: 메시지만 (`/ by zero`)
- ⚠️ `toString()` 줄은 `<`가 빠져(`%=exception.toString()%>`) 스크립트가 아닌 **일반 텍스트로 그대로 출력**됩니다(4번 이슈).

#### ⑥ 📄 `tryCatch.jsp` — 입력 폼
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<html>
<head>
<title>Exception</title>
</head>
<body>
	<form action="tryCatch_process.jsp" method="post">
		<p>숫자1 : <input type="text" name="num1">
		<p>숫자2 : <input type="text" name="num2">
		<p><input type="submit" value="전송">
	</form>
</body>

```

#### 📄 `tryCatch_process.jsp` — try-catch + 포워딩
```jsp
<%@ page contentType="text/html; charset=utf-8"%>
<html>
<head>
<title>Exception</title>
</head>
<body>	   
<%
	try {
		String num1 = request.getParameter("num1");
		String num2 = request.getParameter("num2");
		int a = Integer.parseInt(num1);
		int b = Integer.parseInt(num2);
		int c = a / b;
	} catch (NumberFormatException e) {
		RequestDispatcher dispatcher = request.getRequestDispatcher("tryCatch_error.jsp");
		dispatcher.forward(request, response);
	}
%>
</body>
</html>
```
**동작 원리:**
- 스크립틀릿 안에서 Java의 `try-catch`로 예외를 **직접** 잡습니다 (가장 우선하는 처리 방식).
- `NumberFormatException`(숫자가 아닌 입력)이 발생하면 `request.getRequestDispatcher(...).forward(request, response)`로 오류 페이지에 **포워딩** — 같은 `request` 객체를 넘기므로 오류 페이지에서도 입력값을 읽을 수 있습니다.
- `RequestDispatcher`는 `javax.servlet` 패키지에 있지만 JSP에서는 기본 import되어 별도 `import` 없이 사용합니다.

#### 📄 `tryCatch_error.jsp`
```jsp

<head>

```
**동작 원리:**
- `forward`로 전달된 원래 요청의 파라미터(`num1`, `num2`)를 그대로 다시 읽어서 사용자가 잘못 입력한 값을 보여줍니다.

## 3. 핵심 JSP/Java 태그 및 문법

### 3-1. 예외 처리 방법 비교

| 방법 | 설정 | 적용 범위 | 특징 |
|---|---|---|---|
| `errorPage` 속성 | `<%@ page errorPage="x.jsp" %>` | 해당 JSP 한 페이지 | 페이지마다 개별 지정 |
| `isErrorPage` 속성 | `<%@ page isErrorPage="true" %>` | 오류 페이지 쪽 선언 | `exception` 내장 객체 사용 가능 |
| `web.xml` 오류 코드 | `<error-page><error-code>500</error-code>...` | 웹 앱 전체 | 404, 500 등 HTTP 상태 코드 기준 |
| `web.xml` 예외 유형 | `<error-page><exception-type>java.lang.Exception</exception-type>...` | 웹 앱 전체 | 예외 클래스 기준, 오류 코드보다 우선 |
| `try-catch-finally` | 스크립틀릿 안 Java 코드 | 코드 블록 | 가장 우선, 예외별로 세밀한 처리 |

### 3-2. `web.xml` `<error-page>` 설정 예시 (교재 형식)

```xml
<error-page>
	<error-code>500</error-code>
	<location>/errorCode_error.jsp</location>
</error-page>

<error-page>
	<exception-type>java.lang.Exception</exception-type>
	<location>/exceptionType_error.jsp</location>
</error-page>
```

### 3-3. `exception` 내장 객체의 주요 메서드

| 메서드 | 반환 | 예 (`0`으로 나눴을 때) |
|---|---|---|
| `getMessage()` | 오류 메시지 | `/ by zero` |
| `toString()` | 클래스명 + 메시지 | `java.lang.ArithmeticException: / by zero` |
| `getClass().getName()` | 예외 클래스 전체 이름 | `java.lang.ArithmeticException` |
| `printStackTrace()` | 스택 추적 출력 (콘솔) | — |

### 3-4. 이번 실습에서 만나는 예외

| 예외 | 발생 상황 |
|---|---|
| `NullPointerException` | 없는 파라미터(`null`)에 `.toUpperCase()` 호출 |
| `NumberFormatException` | `Integer.parseInt("abc")` 등 숫자가 아닌 문자열 변환 |
| `ArithmeticException` | 정수를 `0`으로 나눔 |

## 4. ⚠️ 오늘 발견된 이슈 (다음 실습 시 확인/수정 필요)

| 위치 | 증상 | 원인 |
|---|---|---|
| `WEB-INF/web.xml` | ④ `errorCode`, ⑤ `exceptionType` 실습에서 만든 오류 페이지가 표시되지 않고 Tomcat 기본 500 화면이 나옴 | `web.xml`에 10장 시큐리티 설정만 있고 `<error-page>` 매핑(3-2)이 없음 |
| `exception_error.jsp` | `toString() : %=exception.toString()%>` 문자열이 화면에 그대로 출력됨 | 표현식 태그 앞의 `<` 누락 (`<%=exception.toString()%>`가 되어야 함) |
| `tryCatch_process.jsp` | 정상 입력 시 화면에 아무것도 표시되지 않음 | 계산 결과 `c`를 출력하는 코드가 없음 |
| `tryCatch_process.jsp` | 숫자2에 `0` 입력 시 Tomcat 기본 500 화면 | `NumberFormatException`만 잡고 `ArithmeticException`은 잡지 않으며, `errorPage` 지정도 없음 |
| `errorCode_error.jsp` | 안내 문구가 "505 오류" | 처리되지 않은 예외의 HTTP 상태 코드는 500 (505는 HTTP 버전 미지원 코드) |

## 5. 💡 핵심 문법 정리 표 (Key Takeaways)

| 개념 | 설명 | 예시 |
|---|---|---|
| `errorPage` 속성 | 이 페이지에서 예외 발생 시 이동할 페이지 | `<%@ page errorPage="error.jsp" %>` |
| `isErrorPage` 속성 | 오류 처리 페이지 선언 → `exception` 객체 사용 | `<%@ page isErrorPage="true" %>` |
| `exception` 내장 객체 | 발생한 예외(`Throwable`) | `<%= exception.getMessage() %>` |
| `<error-code>` | HTTP 상태 코드별 오류 페이지 | `<error-code>404</error-code>` |
| `<exception-type>` | 예외 클래스별 오류 페이지 (코드보다 우선) | `java.lang.ArithmeticException` |
| `try-catch` | 스크립틀릿에서 직접 예외 처리 (최우선) | `catch (NumberFormatException e)` |
| `RequestDispatcher.forward()` | 같은 요청 객체를 유지한 채 다른 페이지로 이동 | `request.getRequestDispatcher("x.jsp").forward(request, response)` |
| 처리 우선순위 | try-catch → errorPage → exception-type → error-code → 기본 화면 | — |
