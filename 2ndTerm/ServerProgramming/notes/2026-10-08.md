# 📅 2026-10-08 서버 프로그래밍 실습 정리

> **교재 10장 — 시큐리티 (Security)**
> Tomcat 컨테이너가 제공하는 **선언적 보안(web.xml)** 과 **FORM 인증 방식**으로 특정 페이지에 역할(role) 기반 접근 제한을 걸고, `request` 내장 객체의 보안 관련 메서드로 인증 정보를 확인하는 실습

## 2. 실습 파일 목록 및 전체 원본 코드

---

#### 📄 `WEB-INF/web.xml` — 선언적 보안 설정
```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app>
	<security-role>
		<role-name>role1</role-name>
	</security-role>
	<security-constraint>
		<web-resource-collection>
			<web-resource-name>JSPBook</web-resource-name>
			<url-pattern>/security02.jsp</url-pattern>
			<http-method>GET</http-method>
		</web-resource-collection>
		<auth-constraint>
			<description></description>
			<role-name>role1</role-name>
		</auth-constraint>
	</security-constraint>
	<login-config>
		<auth-method>FORM</auth-method>
		<form-login-config>
			<form-login-page>/login.jsp</form-login-page>
			<form-error-page>/login_failed.jsp</form-error-page>
		</form-login-config>
	</login-config>
</web-app>
```
**동작 원리:**
- `<security-role>`: 이 웹 애플리케이션에서 사용할 역할 이름(`role1`)을 선언합니다. 실제 사용자와 역할의 연결은 Tomcat의 `tomcat-users.xml`에서 합니다.
- `<security-constraint>`: 보호할 자원과 접근 조건을 정의합니다.
  - `<web-resource-collection>`: `/security02.jsp`에 대한 **GET 요청**만 보호 대상 (`<http-method>`를 생략하면 모든 메서드가 보호됨)
  - `<auth-constraint>`: `role1` 역할을 가진 사용자만 접근 허용
- `<login-config>`:
  - `<auth-method>FORM</auth-method>`: 브라우저 기본 팝업(BASIC) 대신 **개발자가 만든 로그인 페이지**로 인증
  - `<form-login-page>` / `<form-error-page>`: 로그인 폼 페이지와 인증 실패 페이지 경로 (웹앱 루트 기준)
- 코드 한 줄 없이 설정만으로 보안을 적용하므로 **선언적 보안(declarative security)** 이라 부릅니다.

---

#### 📄 `login.jsp` — FORM 인증 로그인 페이지
```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Security</title>
</head>
<body>
	<form name="loginForm" action="j_security_check" method="post">
		<p> 사용자명: <input type="text" name="j_username">
		<p> 비밀번호: <input type="password" name="j_password">
		<p> <input type="submit" value="전송">
	</form>
</body>
</html>
```
**동작 원리:**
- FORM 인증은 이름이 **정해져 있는** 세 가지를 반드시 지켜야 합니다.
  - `action="j_security_check"`: Tomcat이 가로채서 인증을 처리하는 예약된 URL
  - `name="j_username"`, `name="j_password"`: 사용자명·비밀번호 필드의 예약된 이름
- `method="post"`: 비밀번호가 URL에 노출되지 않도록 POST 사용
- 사용자가 이 페이지 주소를 직접 열어서 제출하는 것이 아니라, **보호된 페이지를 요청했을 때 Tomcat이 대신 보여주는** 페이지입니다.

---

#### 📄 `login_failed.jsp` — 인증 실패 페이지
```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Security</title>
</head>
<body>
	<p> 인증 실패했습니다.
</body>
</html>
```
**동작 원리:**
- 사용자명/비밀번호가 틀렸을 때 `web.xml`의 `<form-error-page>` 설정에 따라 표시됩니다.
- 참고: 로그인은 성공했지만 **역할이 맞지 않는 경우**(예: `tomcat` 역할만 가진 사용자)는 이 페이지가 아니라 **HTTP 403 Forbidden** 오류가 납니다.

---

#### 📄 `security01.jsp` — 인증 성공 안내 페이지
```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Security</title>
</head>
<body>
	<p> 인증 성공했습니다.
</body>
</html>
```
**동작 원리:**
- 교재 예제에서 BASIC 인증 실습(`/security01.jsp`를 보호)에 쓰이는 페이지입니다. 이 프로젝트의 `web.xml`은 `/security02.jsp`만 보호하므로, `security01.jsp`는 **로그인 없이 바로 열립니다**.

---

#### 📄 `security02.jsp` — 🔒 보호 대상 페이지 (인증 정보 출력)
```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Security</title>
</head>
<body>
	<p> 사용자명 : <%=request.getRemoteUser() %> 
	<p> 인증방법 : <%=request.getAuthType() %> 
	<p> 인증한 사용자명이 역할명 "tomcat"에 속하는 사용자인가요? 
		<%=request.isUserInRole("tomcat") %>
	<p> 인증한 사용자명이 역할명 "role1"에 속하는 사용자인가요?
		<%=request.isUserInRole("role1") %> 
</body>
</html>
```
**동작 원리:**
- `request.getRemoteUser()`: 인증된 사용자명 (미인증이면 `null`)
- `request.getAuthType()`: 인증 방식 — 이 프로젝트에서는 `FORM`
- `request.isUserInRole("역할명")`: 로그인한 사용자가 해당 역할을 가졌는지 `true`/`false`
- 이 페이지는 `role1`만 접근 가능하므로 `isUserInRole("role1")`은 항상 `true`. `tomcat` 역할도 함께 가진 사용자(`tomcat-users.xml`의 `both` 계정처럼 `roles="tomcat,role1"`)로 로그인하면 두 값이 모두 `true`가 됩니다.
- 이처럼 JSP 코드 안에서 역할을 확인해 화면을 다르게 보여주는 방식을 **프로그래밍적 보안(programmatic security)** 이라 합니다.

## 3. 핵심 JSP/Java 태그 및 문법

### 3-1. 시큐리티 처리 방식 비교

| 방식 | 설정 위치 | 특징 |
|---|---|---|
| 선언적 보안 | `web.xml`의 `<security-constraint>` | 코드 수정 없이 URL 단위로 접근 제한 |
| 프로그래밍적 보안 | JSP/서블릿 코드의 `request.isUserInRole()` 등 | 같은 페이지 안에서 역할별로 다른 내용 표시 |

### 3-2. 인증 방식 (`<auth-method>`)

| 값 | 설명 |
|---|---|
| `BASIC` | 브라우저 기본 로그인 팝업 (교재 `ch10_web_BASIC.xml` 예제, `JSPSource/WEB-INF/`에 보관) |
| `FORM` | 개발자가 만든 로그인 페이지 사용 — `j_security_check`, `j_username`, `j_password` 고정 |
| `DIGEST`, `CLIENT-CERT` | 다이제스트 인증 / 클라이언트 인증서 (실습 범위 밖) |

### 3-3. Tomcat 사용자/역할 설정 (`tomcat-users.xml`)

```xml
<role rolename="role1"/>
<user username="사용자명" password="비밀번호" roles="role1"/>
```
- `web.xml`의 `<role-name>`과 `tomcat-users.xml`의 `rolename`이 같아야 접근이 허용됩니다.
- 이 파일은 계정 정보를 담고 있어 `Servers/` 폴더째 Git 추적에서 제외되어 있습니다. 문서에도 비밀번호는 옮기지 않습니다.

## 4. ⚠️ 오늘 발견된 이슈 (확인 필요)

| 위치 | 내용 |
|---|---|
| `Servers/.../tomcat-users.xml` | `username="admin"` 사용자가 두 번 정의되어 있음(하나는 `manager-gui`, 하나는 `admin` 역할). Tomcat 사용자 DB는 사용자명을 키로 저장하므로 한 이름에 정의가 하나만 남습니다(보통 나중 정의가 앞의 것을 덮어씀). 이 경우 `admin` 계정에는 `admin` 역할만 남고 Tomcat 관리 화면용 `manager-gui` 권한은 사라질 수 있으니, 두 용도가 모두 필요하면 사용자명을 나누거나 `roles="manager-gui,admin"`처럼 한 줄로 합치는 것을 고려 (Git 미추적 파일이라 문서에만 기록) |
| `security01.jsp` | 현재 `web.xml`의 보호 대상이 아니므로 "인증 성공했습니다" 문구가 로그인 없이도 표시됨 (교재 BASIC 예제용 페이지) |

## 5. 💡 핵심 문법 정리 표 (Key Takeaways)

| 개념 | 설명 | 예시 |
|---|---|---|
| `<security-role>` | 웹 앱에서 사용할 역할 이름 선언 | `<role-name>role1</role-name>` |
| `<security-constraint>` | 보호할 URL·HTTP 메서드와 허용 역할 지정 | `<url-pattern>/security02.jsp</url-pattern>` |
| `<auth-constraint>` | 접근 허용 역할 | `<role-name>role1</role-name>` |
| `<login-config>` | 인증 방식과 로그인/오류 페이지 | `<auth-method>FORM</auth-method>` |
| `j_security_check` | FORM 인증 처리용 예약 URL | `<form action="j_security_check" method="post">` |
| `j_username` / `j_password` | FORM 인증 예약 필드 이름 | `<input name="j_username">` |
| `request.getRemoteUser()` | 인증된 사용자명 | `<%= request.getRemoteUser() %>` |
| `request.getAuthType()` | 인증 방식 이름 | `FORM`, `BASIC` |
| `request.isUserInRole()` | 역할 보유 여부 | `request.isUserInRole("role1")` |
| 인증 실패 vs 권한 없음 | 비밀번호 오류 → `form-error-page` / 역할 불일치 → 403 | — |
| `tomcat-users.xml` | Tomcat 메모리 영역(Realm)의 사용자·역할 정의 | `<user ... roles="role1"/>` |
