## 2. 실습 파일 목록 및 전체 원본 코드

실습은 검증 수준이 점진적으로 강화되는 5단계로 구성됩니다: **① 검증 없음 → ② 빈 값 체크 → ③ 길이 체크 → ④ 문자 종류 체크 → ⑤ 정규식 종합 검증**.

---

#### 📄 `validation01.jsp` — 검증 없이 값만 확인 (출발점)

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Validation</title>
</head>

<script type="text/javascript">
	function checkForm() {
		alert("아이디 : " + document.loginForm.id.value + "\n" + 
				"비밀번호 : " + document.loginForm.passwd.value);
	}
</script>
<body>
	<form name = "loginForm">
		<p> 아 이 디 : <input type = "text" name = "id">
			<input type = "submit" value = "전송" onclick = "checkForm()">
	</form>
</body>
</html>
```

**동작 원리:**
- `document.loginForm.id.value`처럼 `document.폼이름.필드이름.value`로 DOM에 접근하는 가장 기본적인 방식입니다. `id="..."` 속성이 없어도 `name` 속성만으로 `document.loginForm`, `document.loginForm.id`가 자동으로 참조됩니다(브라우저의 named-access 기능).
- `<input type="submit">`에 `onclick`을 걸어놓았지만 `checkForm()`이 `false`를 반환하지 않고, `<form>`에 `action`도 없으므로, alert 창이 뜬 뒤 결국 자기 자신(현재 페이지)으로 제출되어 새로고침됩니다. 이 단계는 "검증"이 아니라 "입력값을 자바스크립트에서 읽어오는 법"만 보여주는 도입 단계입니다.
- 비밀번호 필드(`passwd`)는 스크립트에서 참조하지만 실제 `<input name="passwd">`가 폼에 없어, 제출 시 `undefined`가 alert에 표시됩니다.

#### 📄 `validation02.jsp` — 빈 값(공백) 체크

```jsp
<%@ page contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Validation</title>
</head>

<script type="text/javascript">
	function checkLogin() {
		var form = document.loginForm;
		if (form.id.value == ""){
			alert("아이디를 입력해주세요.");
			form.id.focus();
			return false;
		} else if (form.passwd.value==""){
			alert("비밀번호를 입력해주세요");
			form.passwd.focus();
			return false;
		}
		form.submit();
	}
</script>
<body>
	<form name = "loginForm" action = "valiation02_process.jsp" method = "post">
		<p> 아 이 디 : <input type = "text" name = "id">
		<p> 비밀번호 : <input type = "password" name = "passwd">
		<input type = "button" value = "전송" onclick = "checkLogin()">
	</form>
</body>
</html>
```

**동작 원리:**
- `<input type="button">`(submit이 아님)로 바꾸고 `onclick="checkLogin()"`을 걸어, **검증을 통과했을 때만 `form.submit()`을 명시적으로 호출**하는 패턴으로 전환되었습니다. 01번과 가장 큰 구조적 차이입니다 — 검증 실패 시 `return false`로 함수만 종료되며 폼 자체는 전송되지 않습니다.
- `form.id.value == ""` — 공백 문자만 입력해도(예: `"   "`) 이 조건은 `false`이므로 통과됩니다(트리밍 없음). 실질적으로 "완전히 빈 문자열"만 걸러냅니다.
- `form.id.focus()`: 오류가 난 입력 필드로 커서를 이동시켜 사용자 경험을 개선합니다.

> ⚠️ **오탈자 버그**: `<form>`의 `action = "valiation02_process.jsp"`가 `validation02_process.jsp`(l 누락)로 오타나 있습니다. 실제 파일명은 `validation02_process.jsp`이므로, 이 폼을 그대로 제출하면 **404 Not Found**가 발생합니다.

#### 📄 `validation02_process.jsp` — 02 제출 처리

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Validation</title>
</head>
<body>
	<h3> 입력에 성공했습니다. </h3>
	<%
		request.setCharacterEncoding("utf-8");
		String id = request.getParameter("id");
		String passwd = request.getParameter("passwd");
	%>
	
	<p> 아 이 디 : <%=id %>
	<p> 비 밀 번 호 : <%=passwd %>	
</body>
</html>
```

**동작 원리:**
- `request.setCharacterEncoding("utf-8")`을 파라미터를 읽기 **전에** 호출해야 한글이 깨지지 않습니다(POST 파라미터 디코딩 인코딩을 지정하는 시점이 중요).
- `request.getParameter("id")`로 이전 페이지 폼의 `name="id"` 값을 그대로 받아 `<%= %>` 표현식 태그로 출력합니다. 클라이언트 검증을 통과한 값이 서버로 넘어왔음을 확인하는 용도의 단순 에코(echo) 페이지입니다.

#### 📄 `validation03.jsp` — 길이(자릿수) 체크

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Validation</title>
</head>

<script type="text/javascript">
	function checkLogin() {
		var form = document.loginForm;
		
		if (form.id.value.length < 4 || form.id.value.length > 12) {
			alert ("아이디는 4~12자 이내로 입력 가능합니다");
			form.id.select();
			return;
		}
		
		if (form.passwd.value.length < 4) {
			alert("비밀번호는 4자 이상으로 입력해야 합니다");
			form.passwd.select();
			return;
		}
		
		form.submit();
	}

</script>

<body>
	<form name = "loginForm" action="validation03_process.jsp" method="post">
		<p> 아이디 : <input type = "text" name = "id">
		<p> 비밀번호 : <input type = "password" name = "passwd">
		<p> <input type = "button" value = "전송" onclick = "checkLogin()">
	</form>

</body>
</html>
```

**동작 원리:**
- `String.length` 프로퍼티로 문자 수를 비교합니다. 02번의 "빈 값" 체크보다 한 단계 발전해, 최소/최대 길이 범위(`4~12자`)까지 검사합니다.
- `form.id.select()`: `focus()`와 달리 필드 안의 기존 텍스트까지 전체 선택(드래그 상태)해, 사용자가 바로 다시 입력할 수 있게 합니다.
- 02번과 달리 `return false` 대신 `return`(값 없는 반환)을 사용하는데, 함수 자체가 `onclick`의 반환값으로 쓰이지 않으므로(버튼이 `submit` 타입이 아니라 `button` 타입) 동작상 차이는 없습니다.

#### 📄 `validation04.jsp` — 문자 종류(영문/숫자) 체크

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Validation</title>
</head>

<script type="text/javascript">
	function checkLogin() {
		var form = document.loginForm;
		
		for(i=0 ; i < form.id.value.length; i++){
			var ch = form.id.value.charAt(i);
			
			if ((ch < 'a' || ch > 'z') && (ch > 'A' || ch <'Z') && (ch > '0' || ch < '9')){
				alert("아이디는 영문 소문자만 입력 가능합니다.");
				form.id.select();
				return;
			}
		}
		if (isNaN(form.passwd.value)) {
			alert("비밀번호는 숫자만 입력 가능합니다.");
			form.passwd.select();
			return;
		}
		form.submit();
	}
</script>

<body>
	<form name = "loginForm" action="validation04_process.jsp" method="post">
		<p> 아이디 : <input type = "text" name="id">
		<p> 비밀번호 : <input type = "password" name="passwd">
		<p> <input type="button" value="전송" onclick="checkLogin()">
	</form>
</body>
</html>
```

**동작 원리:**
- `for` 루프 + `charAt(i)`로 아이디 문자열을 한 글자씩 순회하며, 각 글자가 소문자 알파벳 범위(`'a'`~`'z'`)를 벗어나는지 문자 코드 비교(`<`, `>`)로 검사합니다.
- `isNaN(form.passwd.value)`: 문자열을 숫자로 변환할 수 없으면 `true`를 반환하는 내장 함수로, 비밀번호가 "숫자로만" 이루어졌는지 검사합니다.
- `var i`가 `for` 문 안에서 `var` 없이 선언되어 있어(`for(i=0 ...)`) 암묵적 전역 변수가 됩니다. 동작에는 영향이 없지만 전역 스코프를 오염시키는 안 좋은 습관입니다.

> ⚠️ **조건식 버그**: `(ch < 'a' || ch > 'z') && (ch > 'A' || ch <'Z') && (ch > '0' || ch < '9')`에서 뒤의 두 항 `(ch > 'A' || ch < 'Z')`와 `(ch > '0' || ch < '9')`는 사실상 **거의 모든 문자에 대해 항상 참**입니다(예: `ch > 'A'`이거나 `ch < 'Z'`이거나 둘 중 하나는 대부분 성립). 즉 실제로는 맨 앞의 `(ch < 'a' || ch > 'z')`(소문자 범위 밖인지)만으로 알람 여부가 결정되고, 뒤의 두 `&&` 항은 사실상 아무 역할도 하지 못하는 죽은 코드(dead condition)입니다. 지금은 "소문자만 허용"이라는 의도와 우연히 같은 결과를 내지만, 만약 "숫자나 대문자는 별도로 다르게 처리"하려는 의도가 있었다면 이 조건식으로는 그 의도를 구현하지 못합니다.

#### 📄 `validation05.jsp` — 정규식 기반 회원가입 종합 검증

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>Validation</title>
</head>

<script type="text/javascript">
	function checkMember() {
		var regExpId = /^[a-z|A-Z|ㄱ-ㅎ|ㅏ-ㅣ|가-힣]/;
		var regExpName = /^[가-힣]*$/;
		var regExpPasswd = /^[0-9]*$/;
		var regExpPhone = /^\d{3}-\d-{3,4}-\d{4}$/;
		var regExpEmail = /^[0-9a-zA-Z]([-_\.]?[0-9a-zA-Z])*@[0-9a-zA-Z]([-_\.]?[0-9a-zA-Z])*\.[a-zA-Z]{2,3}$/i;

		var form = document.Member;
		
		var id = form.id.value;
		var name = form.name.value;
		var passwd = form.passwd.value;
		var phone = form.phone1.value + "-" + form.phone2.value + "-" + form.phone3.value;
		var email = form.email.value;
		
		if (!regExpId.test(id)) {
			alert("아이디는 문자로 시작해주세요");
			form.id.select();
			return;
		}
		
		if (!regExpName.test(name)) {
			alert("이름은 한글만 입력해주세요");
			return;
		}
		
		if (!regExpPasswd.test(passwd)) {
			alert("이름은 한글만 입력해주세요");
			return;
		}
		
		if (!regExpPhone.test(phone)) {
			alert("연락처 입력을 확인해주세요");
			return;
		}
		
		if (!regExpEmail.test(email)) {
			alert("이메일 입력을 확인해 시작해주세요");
			return;
		}
		
		form.submit();
	}
	
</script>

<body>
	<h3>회원 가입</h3>
	<form action = "validation05_process.jsp" name="Member" method="post">
		<p> 아이디 : <input type = "text" name="id">
		<p> 비밀번호 : <input type = "password" name="passwd">
		<p> 이름 : <input type = "text" name ="name">
		<p> 연락처 : <select name = "phone1">
			<option value = "010">010</option>
			<option value = "011">011</option>
			<option value = "016">016</option>
			<option value = "017">017</option>
			<option value = "019">019</option>
		</select> - <input type = "text" maxlength="4" size="4" name="phone2"> - <input type="text" maxlength="4" size="4" name="phone3">
		<p> 이메일 : <input type="text" name="email">
		<p> <input type="button" value="가입하기" onclick="checkMember()">
	</form>
</body>
</html>
```

**동작 원리:**
- 이전 단계들의 수작업 문자 비교(`charAt`, `<`, `>`)를 모두 **정규식(RegExp) + `test()`** 방식으로 교체한 최종 단계입니다. `select` 태그(휴대폰 앞자리)와 `text` 입력 2개(`phone2`, `phone3`)를 문자열 결합(`+`)으로 하나의 전화번호 문자열로 합쳐 검증하는 패턴도 새로 등장합니다.
- `regExpId = /^[a-z|A-Z|ㄱ-ㅎ|ㅏ-ㅣ|가-힣]/`: 문자 클래스(`[...]`) 안의 `|`는 정규식의 "OR" 연산자가 아니라 **리터럴 파이프 문자 자체**로 취급됩니다. 즉 이 정규식은 "아이디의 첫 글자가 소문자/대문자/한글 자모/완성형 한글 중 하나이거나, 혹은 문자 그대로의 `|` 자체여도 통과"하는 의미가 되어, 의도(문자로 시작)는 우연히 거의 맞지만 `|`가 아이디 첫 글자로 허용되는 의도치 않은 구멍이 있습니다. `$`(끝 고정)도 없어 첫 글자만 검사하고 나머지는 검사하지 않습니다.
- `regExpEmail`의 `/i` 플래그는 대소문자를 구분하지 않고 매칭하겠다는 의미인데, 이메일 정규식 자체가 이미 `a-zA-Z`로 대소문자를 모두 포함하고 있어 사실상 불필요한 플래그입니다.

> ⚠️ **정규식 버그**: `regExpPhone = /^\d{3}-\d-{3,4}-\d{4}$/`에서 `\d-{3,4}`는 "숫자 1개 뒤에 하이픈(`-`)이 3~4번 반복"으로 해석됩니다(`{3,4}` 수량자가 바로 앞의 `-` 문자에만 적용됨). 즉 `010-1234-5678`처럼 하이픈이 1개씩만 있는 정상적인 전화번호 형식은 이 정규식과 **매칭되지 않습니다**. 의도한 정규식은 아마 `/^\d{3}-\d{3,4}-\d{4}$/`(가운데 자리 3~4자리 숫자)였을 것으로 보입니다.
> 또한 비밀번호 검증 실패(`regExpPasswd`) 시 alert 메시지가 `"이름은 한글만 입력해주세요"`로 되어 있어(이름 검증 메시지를 복사하며 문구를 고치지 않은 것으로 보임) 실제 원인(숫자만 입력해야 함)과 다른 안내가 표시됩니다.

## 3. 핵심 JSP/Java 태그 및 문법

### 3-1. 클라이언트 사이드 검증의 기본 패턴

| 패턴 | 설명 |
|---|---|
| `<input type="button" onclick="fn()">` | `submit` 타입 대신 `button` 타입을 써서, 브라우저의 기본 제출 동작을 아예 발생시키지 않고 자바스크립트 함수 호출만 트리거 |
| 함수 내부에서 `form.submit()` | 검증을 모두 통과했을 때만 폼을 코드로 직접 제출 — "검증 후 제출" 흐름의 핵심 |
| 검증 실패 시 `return`/`return false` | 함수를 즉시 종료해 `form.submit()`에 도달하지 못하게 함 |
| `field.focus()` / `field.select()` | 오류 필드로 커서 이동(`focus`) 또는 기존 값 전체 선택(`select`)으로 재입력 유도 |
| `document.폼name.필드name` | `name` 속성 기반의 DOM 접근(named access) — `getElementById` 없이도 폼과 필드에 접근 가능 |

### 3-2. 문자열 검증 수단의 단계적 발전

| 단계 | 수단 | 예시 |
|---|---|---|
| 02 | 빈 문자열 비교 | `value == ""` |
| 03 | 길이(`length`) 비교 | `value.length < 4` |
| 04 | 문자 코드 순회 비교 + `isNaN()` | `charAt(i)`, `ch < 'a' \|\| ch > 'z'` |
| 05 | 정규식(`RegExp`) + `test()` | `/^[0-9]*$/.test(value)` |

### 3-3. 정규식(RegExp) 리터럴 문법

| 요소 | 의미 |
|---|---|
| `/패턴/` | 정규식 리터럴 (슬래시로 감쌈) |
| `^`, `$` | 문자열의 시작 / 끝 고정 (없으면 부분 일치도 통과) |
| `[...]` | 문자 클래스 — 대괄호 안의 문자 중 하나 (단, `\|`는 OR이 아니라 리터럴 문자) |
| `{n,m}` | 바로 앞 요소가 n~m번 반복 (적용 대상이 문자 하나인지 그룹인지 주의) |
| `*` | 0회 이상 반복 |
| `regExp.test(str)` | 문자열이 패턴과 일치하면 `true` 반환 |
| `/i` 플래그 | 대소문자 구분 없이 매칭 |

## 5. 💡 핵심 문법 정리 표 (Key Takeaways)

| 개념 | 설명 | 예시 |
|---|---|---|
| Named DOM access | `name` 속성만으로 `document.폼이름.필드이름` 접근 가능 | `document.loginForm.id.value` |
| `type="button"` + `onclick` | 폼 기본 제출을 막고 검증 함수만 실행 | `<input type="button" onclick="checkLogin()">` |
| `form.submit()` | 검증 통과 후 자바스크립트로 명시적 제출 | 검증 함수 마지막 줄 |
| `field.focus()` / `field.select()` | 오류 필드로 포커스 이동 / 값 전체 선택 | `form.id.focus()` |
| `String.length` | 문자열 길이(자릿수) 검증 | `value.length < 4` |
| `charAt(i)` + 문자 코드 비교 | 한 글자씩 순회하며 허용 범위 판정 | `ch < 'a' \|\| ch > 'z'` |
| `isNaN(value)` | 숫자로 변환 가능한지 여부 판정 | `isNaN(form.passwd.value)` |
| `RegExp.test(str)` | 정규식 패턴과 문자열의 일치 여부(boolean) | `/^[0-9]*$/.test(passwd)` |
| 정규식 문자 클래스 `[...]` | 대괄호 안 문자 "중 하나" — `\|`는 OR이 아닌 리터럴 취급 | `[a-z\|A-Z]` (의도와 다르게 동작) |
| 수량자 `{n,m}`의 적용 범위 | 바로 앞의 단일 문자/그룹에만 적용됨을 주의 | `\d-{3,4}` ≠ `\d{3,4}` |
| `request.setCharacterEncoding()` | 파라미터를 읽기 전에 호출해야 한글 파라미터가 깨지지 않음 | `request.setCharacterEncoding("utf-8")` |
